# CAPS

**A notebook LLM for students** — upload a PDF, ask questions about it, and watch the Paritok
compression engine cut your context tokens in real time.

CAPS routes every question through [Paritok](https://paritok.com) — a 4B-parameter language model
running on a hosted GPU — which compresses the document context **per request, per question**, before
the answer is generated by Groq's LLM. An ON/OFF toggle shows you the measured token, cost, and
latency impact of compression for the very same question.

## How it works

```
 Student uploads PDF
   │
   ▼
 PDF parsed → chunked into ~3k-char segments
   │
   ▼
 Student asks a question  ──────────────────────────────┐
   │                                                    │
   ├─ Paritok ON: each matching chunk is compressed     │
   │   by the hosted GPU (query-aware)                  │
   │   POST /api/compress → { compressed, ... }         │
   │                                                    ▼
   └─ Context + question ───────────────────────► Groq (llama-3.3-70b)
                                                    │
                                                    ▼
                                              Answer streams back
                                                 │
                                     Groq usage.prompt_tokens measured
                                     on BOTH paths → real token savings
```

- **Paritok ON** — context is compressed first (`src/app/api/chat/route.ts` → `src/lib/paritok.ts`).
- **Paritok OFF** — the same context goes to Groq uncompressed, giving a genuine baseline.
- The Session panel compares `usage.prompt_tokens` from both modes live.

## Features

- PDF upload → text extraction → retrieval + chunking (no vector DB needed)
- Query-aware retrieval picks the most relevant segments per question
- Real A/B toggle: compressed vs. uncompressed, same question
- Live Session panel: tokens used (with/without), % saved, cost saved, avg latency
- ChatGPT-style UI, light/dark mode

## Tech stack

- Next.js 16 (App Router, Route Handlers), React 19, TypeScript, Tailwind v4
- [Groq](https://groq.com) — free, fast upstream LLM (`llama-3.3-70b-versatile`)
- [Paritok](https://paritok.com) — hosted GPU compression of the document context
- `unpdf` for PDF text extraction

## Setup

```bash
bun install

# 1. Add your keys (never commit .env.local)
cp .env.example .env.local
#   GROQ_API_KEY=...
#   PARITOK_API_KEY=...

# 2. Run it
bun run dev        # http://localhost:3000
```

## Configuration (`.env.local`)

| Variable | Description |
| --- | --- |
| `GROQ_API_KEY` | Your Groq key (https://console.groq.com/keys) |
| `PARITOK_API_KEY` | Your Paritok key (https://paritok.com) |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Vercel KV credentials — only needed when deployed (local dev uses an in-memory store) |
| `GROQ_MODEL` | Model to answer with (default `llama-3.3-70b-versatile`) |
| `GROQ_INPUT_PRICE_PER_1M` | Input token price in USD per 1M (default `0.59`) |
| `GROQ_OUTPUT_PRICE_PER_1M` | Output token price in USD per 1M (default `0.79`) |

> The proxy call to Paritok's hosted GPU is `POST https://www.paritok.com/api/compress`
> with `{ "content", "query", "kind": "file_read" }` → `{ "compressed", "gpu_available" }`.
> Compressed segments are cached per (content-hash, query) so repeated questions are instant.

## Deploy to Vercel

1. Push this repo to GitHub.
2. Import it at [vercel.com](https://vercel.com/new) — Next.js is auto-detected.
3. In your Vercel project, **Storage → Create Database → KV** (free tier).
4. Add the environment variables (Project Settings → Environment Variables):
   `GROQ_API_KEY`, `PARITOK_API_KEY`, plus the KV credentials Vercel offers to connect.
5. Deploy. The app persists docs/questions in Vercel KV instead of memory.

> Note: the first question after a cold start can take ~30s (Paritok GPU warm-up);
> the free tier may time it out — just ask again.

## Project structure

```
src/
  app/
    api/
      upload/route.ts   # PDF → text → chunks (in-memory store)
      chat/route.ts     # ON/OFF routing: compress via Paritok, then Groq
      stats/route.ts    # live token / cost / latency aggregation
    page.tsx            # chat UI
  components/
    composer.tsx        # Paritok ON/OFF toggle + PDF upload
    chat-home.tsx       # message thread + document chip
    session-stats.tsx   # live Session panel (polls /api/stats)
    sidebar.tsx, icons.tsx
  lib/
    paritok.ts          # hosted compress client + cache
    groq.ts             # Groq chat completions + token/cost math
    pdf.ts              # PDF extraction + chunking
    retrieval.ts        # query-aware chunk selection
    store.ts            # Vercel KV store (in-memory fallback) + stats aggregation
examples/
  caps-sample.pdf       # sample PDF to try
  transcript.md         # example Q&A output
```

## Try it

1. Open `examples/caps-sample.pdf` (mitochondria notes) or your own PDF.
2. Ask a question with **Paritok ON**, then the same question with **Paritok OFF**.
3. Watch the Session panel: ~80–90% fewer prompt tokens with compression.

Example (from `examples/transcript.md`):

| | Paritok OFF | Paritok ON |
| --- | ---: | ---: |
| Prompt tokens | 1,096 | 145 |
| Saved | — | **~87%** |
